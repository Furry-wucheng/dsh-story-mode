# 小说写作流程入口

## 1. 按阶段读取参考文件

本技能包含默认流程。参考文件只在相关阶段读取，不把完整流程和审读面板预先塞进每次写作的上下文：

- [共用写作流程](references/writing-workflow.md)：新写较长作品、复杂续写或结构改写，需要细化人物与节拍时读取相关章节。
- [审读面板](references/review-panel.md)：准备派发独立审读时读取角色表、派发与复核章节。

写正文或改稿前加载 `writing-style-contract`；其中示例按需查阅。skill 工具只加载当前 SKILL.md，不会自动加载参考文件。

参考路径以 skill 工具返回的技能目录为基准，不在其他作品目录里搜索。审读所需规则读不到时如实说明，不声称已完成审读。

**审读员不需要读这些。** 五个角色的身份、阅读边界和报告格式已经作为人设装在他们身上（`references/reviewers/` 下各一份，由 preset 的审读员行在挂载时读出），工具也已被限定为只读。所以**被委派的审读员只执行派发任务**：不加载本技能、不读写作流程、不改文件、不再委派。

## 2. 先让作者确定方向与篇幅

新写或续写正文前，核对交付形态、内容重点和停止位置，以及作者已明确的字数、人物、视角等要求。只有关键选择缺失且无法合理从上下文判断时，用 `ask_user_question` 一次问完。

字数或基调直接影响交付、且无法从请求和前文判断时再问；“写一段”“短一点”可以由主代理选合理篇幅并简短说明。单点目标如“约 2000 字”默认允许约 ±15% 浮动；作者给区间时优先落在区间内。小幅偏差不自动触发补写、删字或新一轮审读。明确的精确字数、最低或最高字数按硬约束处理。

已给出的要求不重复问，已有前文可沿用稳定约定。作者明确要求先看方案时先给方案；要求直接写或范围已清楚时直接写。

较长或复杂的新稿先拟简洁节拍，涉及关系转折时检查谁推动、转折依据与双方状态；方案是否交给作者确认，按其要求和任务复杂度决定。方案阶段不派独立读者。成稿后的独立审读（逻辑与关系轴同一轮）不因“免方案确认”而跳过；自查不算独立审读。

局部修改沿用现稿的有效约束，不为措辞小改重新确认字数；显著扩写或续接新内容时核对新增范围与方向。评价任务不追问无关的创作偏好。

## 3. 范围决定规划内容，不取消流程

分别识别操作（新写、续写、改稿、评价、方案）与交付形态（整篇、片段、单场景、开头、对话）。几千字的单场景也可以是片段；不靠字数或目录结构判定是否必须写完整故事。

| 请求 | 必须完成的工作 |
|---|---|
| 新写或续写整篇、片段、单场景、开头、对话 | 确定范围与停止点 → 按规模规划 → 成稿 → B1 冷读与 B2 逻辑审读 → 按报告修订、必要时复核 → 交付 |
| 整体改稿或实质性改写 | 读取现稿和相关设定 → 按确认范围修改 → B1/B2 独立审读与必要复核 |
| 局部措辞、标点或一句一段的润色 | 读取必要上下文 → 修改 → 主代理核对改动与接缝；若改变事实、动机、因果、视角或动作状态，再派对应审读员 |
| 只要评价 | 阅读获准材料 → 按面板派对应角色 → 汇总意见；不修改正文，不为评价擅造作者设定 |
| 只要方案或大纲 | 明确范围 → 按规模准备人物与节拍；涉及关系转折时核对依据 → 主代理自查 → 交付方案，不自动写正文 |

有关系线时，B2 在成稿后的逻辑审读里一并检查“这一跳有没有依据”；无需另派一位，也不在方案阶段派读者。具体判据见[审读面板](references/review-panel.md)的 §4.0。

新写片段也需独立审读，但规划可以只留在当前任务中，不必为短片段强制新建人物卡和节拍文件。片段无需形成全篇闭环，不为验收补写范围外的故事。

## 4. 文件和工具边界

较长新项目可在获准目录内建立方向、人物卡、节拍和正文记录；短片段可在当前任务中保留简要规划。已有项目沿用原路径，只补受影响内容。新增必要文件前简短说明用途，遵守作者指定的文件范围。

禁止为避免重名或了解背景对其他故事目录执行全局 `glob`、`grep` 或目录枚举。新目录只检查拟用路径是否存在，不列出无关作品。搜索、读取和审读派发都不能超出作者授权。

三个只读工具的定位是**主代理的自查与定位手段**：

- `story_wordcount`：实测字数、记录正文版本、查看场景分布。汇报给作者的数字必须来自它；偏离提示只是数据，不是质量判定或自动改稿命令。
- `story_bible`：人物卡字段核对、术语表读取、与正文的提及次数交叉检查。
- `story_lint`：字面线索清单。**它不进审读流程**——命中不构成违规，未命中不表示稿件合格，视角、时态、情绪是否解释过度、节奏和必要交代都要由审读员结合正文与作者要求判断。它的用途是主代理在自查和修订时定位字面形状（哪一行有疑似套话、哪一行需要回看）。

任何工具输出都不能替代主代理核对或独立审读。

## 5. 独立审读与交付条件

**新稿、续写新增正文、整体改稿和改变故事事实的实质性修改必须独立审读。** 首次成稿派 B1 冷读与 B2 逻辑审读；B3/B4/B5 按实际风险派。纯措辞、标点及不改变事实与阅读含义的局部润色由主代理回读改动和接缝即可。修改了旧报告指出的实质问题时，把受影响范围发回原读者复核。稿件被重写或旧报告可能使读者带入预期时，安排全新 B1 盲读。

五个角色各有专用工具（`subagent_review_b1` … `subagent_review_b5`），人设与只读限制已装在角色身上，派发时只给正文路径、版本、范围及必要材料。后台派发并记录 childId；复核用 `send_message` 发回原读者，忘记地址时用 `list_agents`。需要最终盲读时另起全新读者。

审读员共用宿主名额池，一次会话新建的审读子代理不超过 6 位。派发前用 `list_agents` 查在场读者；复核优先 `send_message` 复用。需要审读但额度不足时标明待审，不虚报验收。

涉及关系推进时，B2 同轮检查因果是否自洽和转折是否有依据；派发消息注明关系线即可。没有关系线时不强加关系轴报告。

**它们是不同视角，不是同一个检查做五遍**：B1 报读不懂、B2 核对故事逻辑与关系轴、B3 报读者的注意力与节奏、B4 对照文风契约、B5 重建动作与空间状态。混合派发才有覆盖面。

作者或读者说“我没看懂”时，先定位困惑：可能是信息顺序、必要依据、句子表达，也可能是有意留白。关系推进或核心转折的问题需核对正文证据，但不预设必须补一拍；按实际原因选择局部澄清或结构调整。

在当前任务中保留正文版本、实际审读员的 childId 与报告、必要的修订复核结果。

需要独立审读的任务若未完成审读，交付时标明待审；局部纯文字修改无需声称“独立审读”。作者明确要求跳过某步骤时按其要求调整，并说明实际检查边界。

正文到达约定停止位置就停止扩写，然后完成该范围的审读与修订。交付用简短说明列出稿件路径、实测字数和审读状态；有未解决项如实指出。只要评价或方案就交付相应成果，不顺手写正文。
