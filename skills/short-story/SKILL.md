# 小说写作流程入口

## 1. 必须先加载参考文件

主代理加载本技能后，在提案、建档或写正文之前，用文件读取工具完整读取以下两份资料：

- [共用写作流程](references/writing-workflow.md)：接稿确认、人物卡、节拍、成稿和修订；完整故事与片段共用。
- [审读面板](references/review-panel.md)：派发规则、版本与复用、五个审读角色的触发条件、汇总验收。

写正文或改稿前还要加载 `writing-style-contract`。skill 工具只加载当前 SKILL.md，不代表链接中的参考文件已经加载；不得凭摘要、链接标题或记忆跳过读取。当前上下文已有同版完整内容时可以复用；内容截断时继续读完，压缩后只剩摘要时重新读取。

参考路径以 skill 工具返回的实际技能目录为基准，不能在故事目录或其他作品目录里搜索。记录已读取的参考路径；读取失败时报告路径和错误并处理，不得在未读规则的情况下直接写稿或声称执行过流程。

**审读员不需要读这些。** 五个角色的身份、阅读边界和报告格式已经作为人设装在他们身上（`references/reviewers/` 下各一份，由 preset 的审读员行在挂载时读出），工具也已被限定为只读。所以**被委派的审读员只执行派发任务**：不加载本技能、不读写作流程、不改文件、不再委派。

## 2. 先让作者确定方向与篇幅

新写或续写正文前，核对作者是否已明确：交付形态与范围、目标字数或字数区间、内容重点和基调、人物关系与口吻、视角、限制及停止位置。缺失的实质选择用 `ask_user_question` 一次问完，等作者回答后再规划和写正文。

**字数未给出且未明确授权你决定时，必须问，片段也一样。** "写一段""短一点""带一点剧情"不等于已确认字数；题材、角色资料写得详细也不等于篇幅和基调已经确定。不能用"已经足够明确""可以合理决定"跳过作者尚未授权的选择。

授权按项目解释："角色自拟"只授权拟角色，不授权决定篇幅、基调或跳过沟通；"字数你定"只免去字数这一问。已给出的要求不重复问，已有前文可沿用视角等稳定约定。作者明确说全部由你决定或不要提问直接写时，可以自行定方向与篇幅，简短说明取值；这不取消人物卡、节拍和独立审读。

方向和字数确定后，给一次简洁方案，包含人物与关系、片段或故事的节拍（每拍注明**谁推动**）、篇幅分配和停止点。**方案先过 §4.0 的关系轴审读再交给作者确认**，两者都完成才写正文。当前会话已批准同一方案，或作者明确要求免确认直接写时不重复确认——但**关系轴审读不因"免确认"而跳过**，它审的是结构，不是要不要问作者。"我希望你写……"本身不视为免去接稿与方案确认。

局部修改沿用现稿的有效约束，缺少新的范围或长度要求时按原范围与原篇幅处理；要求显著扩写、续接新内容时仍要确认新增部分的字数与方向。评价任务不追问无关的创作偏好。

## 3. 范围决定规划内容，不取消流程

分别识别操作（新写、续写、改稿、评价、方案）与交付形态（整篇、片段、单场景、开头、对话）。几千字的单场景也可以是片段；不靠字数或目录结构判定是否必须写完整故事。

| 请求 | 必须完成的工作 |
|---|---|
| 新写或续写整篇、片段、单场景、开头、对话 | 确认方向与字数 → 人物卡和节拍（含每拍推动者）→ **方案先过关系轴审读（§4.0）** → 方案确认 → 成稿 → 独立审读 → 修订复核 → 交付 |
| 整体改稿 | 读取现稿和现有资产 → 核对或补齐受影响的人物卡与节拍（含推动者）→ 按确认范围修改 → 独立审读与复核 |
| 局部润色、改一句或一段 | 读取必要上下文 → 核对涉及的人物卡与当前节拍，缺失时整理最小记录 → 修改 → 独立审读改动与接缝 |
| 只要评价 | 阅读获准材料 → 按面板派对应角色 → 汇总意见；不修改正文，不为评价擅造作者设定 |
| 只要方案或大纲 | 明确范围 → 准备对应人物卡与节拍 → **派 B2 审读方案，含 §4.0 的关系轴两组问答** → 交付方案；不自动写正文 |

**§4.0 关系轴**是区别于五个角色常规核对的一类审读（问的是"这一跳有没有依据"，不是"这里有没有矛盾"），由 B2 在**方案阶段**与**首次成稿后**各做一次。它是整套流程里最便宜的一次拦截：方案阶段发现缺一拍，代价是一句话；成稿后发现，代价是重写整场。派发模板与判据见[审读面板](references/review-panel.md)的 §4.0。

片段必须有本片段的人物卡、节拍和审读。它可以不交代后续、不形成完整人物弧光或故事闭环；不能因此跳过规划和审读，也不能反过来为了规划与验收补写范围外的故事。

## 4. 文件和工具边界

新项目在获准目录内建立方向记录、人物卡、节拍和正文，文件与字段见共用流程；已有项目沿用原路径，补齐相关内容，不重复造一套资产。新增必要文件前简短说明用途。作者明确限制只能改正文文件时，人物与节拍记录保留在当前任务或获准材料中，不越过写入限制，规划和核对仍需完成。

禁止为避免重名或了解背景对其他故事目录执行全局 `glob`、`grep` 或目录枚举。新目录只检查拟用路径是否存在，不列出无关作品。搜索、读取和审读派发都不能超出作者授权。

三个只读工具的定位是**主代理的自查与定位手段**：

- `story_wordcount`：实测字数、记录正文版本、核对场景配额。汇报给作者的数字必须来自它。
- `story_bible`：人物卡字段核对、术语表读取、与正文的提及次数交叉检查。
- `story_lint`：字面线索清单。**它不进审读流程**——命中不构成违规，未命中不表示稿件合格，视角、时态、情绪是否解释过度、节奏和必要交代都要由审读员结合正文与作者要求判断。它的用途是主代理在自查和修订时定位字面形状（哪一行有疑似套话、哪一行需要回看）。

任何工具输出都不能替代主代理核对或独立审读。

## 5. 独立审读与交付条件

所有创作与修改都必须独立审读，不以"只是片段""局部任务""已经跑过 lint"豁免。**派谁、什么条件下派，以审读面板的角色触发条件表为准**：B1/B2 每版都派，B3/B4/B5 命中条件就派。不要让"可选"变成"从不"——条件表里的每一条都是可观测的，命中就该派。

五个角色各有一个专用工具（`subagent_review_b1` … `subagent_review_b5`），人设与只读限制已装在角色身上，派发时**只给变量**：正文路径、版本、范围、必要的改动清单，不要再抄一遍模板。派发一律走后台（不要传 `run_in_background: false`），记录 childId；复核用 `send_message` 发回同一位读者，忘记地址时用 `list_agents`。最终盲读另起一位全新读者。

**审读员有额度，先读面板的「派发预算」。** 宿主的存活子代理名额池默认 8 个，池满再派会被 `ACTIVATION_LIMIT_REACHED` 直接拒绝。本模式自限：**一次会话新建的审读子代理不超过 6 位**（B2 一位、B1 一位、B3/B4/B5 合计最多三位、最终盲读一位），其余每一次审读都是 `send_message` 回原读者——**"每版都派"不等于"每版都新建"**。派发前先看 `list_agents`；额度不够时先复用、再借用边界允许的读者，最后在汇总里标"因额度未派 X，该项待审"，不虚报验收，也不把角色读者换成一个没有边界限制的通用子代理凑数。

**除这五个之外还有一次关系轴审读（§4.0，也由 B2 工具派发）**：方案阶段一次、首次成稿后一次。它不是第六个角色，是 B2 被检查表漏掉的那一半职责。交付说明里单独列它的执行情况；没跑过就写"方案未做关系轴审读"，不要拿五个角色的"没有大结构问题"代替。

**它们是不同视角，不是同一个检查做五遍**：B1 报读不懂、B2 核对故事逻辑与关系轴、B3 报读者的注意力与节奏、B4 对照文风契约、B5 重建动作与空间状态。混合派发才有覆盖面。

**作者说"我没看懂"是指令。** 同一处或同一条线被报两次，或困惑落在关系推进、核心动机、关键转折上时，按结构问题处理（回节拍表找缺哪一拍），不做句子级修补，也不靠加一句解释台词糊过去。把解释补进台词（"他其实早就……"）不能替代补一拍。

在当前任务中保留实际证据：参考文件读取记录、方向与字数的确认或明确授权、人物卡与节拍所在位置、正文版本、各审读员的 childId 与报告、修订复核结果。不能只在回复里声称完成这些步骤。

只有对应范围的规划、写作和审读都完成，才交付已审稿。参考文件不可读或独立审读不可用时，说明具体未完成项；可以提供已完成的待审稿，但不能把自查改称独立审读或宣布流程完成。作者明确要求跳过某步骤时才按其要求调整，并说明实际检查边界，不能从"直接写""快一点"推断免审。

正文到达约定停止位置就停止扩写，然后完成该范围的审读与修订。交付用简短说明列出稿件路径、实测字数和审读状态；有未解决项如实指出。只要评价或方案就交付相应成果，不顺手写正文。
