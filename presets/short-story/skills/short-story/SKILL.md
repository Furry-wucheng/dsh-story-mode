# 短篇小说写作流程

## 0. 开工前：先识别目标形态

**不要问"你要写什么"，先判断这是哪一种。** 判据从作者的措辞和材料里读：

| 信号 | 形态 | 重点 |
|---|---|---|
| 单篇、一次写完、给一稿；或贴来一段草稿要求改 | **单篇精修** | 结构冲刺 + 文风执行。四阶段走完就结束 |
| 提到"系列""连载""这个世界""上一篇""同一个主角"；或工作目录里已有别篇稿件 | **系列连载** | 前三样资产（设定圣经、时间线、术语表）变成一等公民，跨篇一致性优先于单篇完美 |

判不出来时只问一个问题，把两种形态摆出来让作者选：

> 这是独立的一篇，还是某个系列里的一篇？

**形态决定资产结构，所以必须在建目录之前定。** 判错会让素材以错误的粒度沉淀——单篇不需要术语表，系列缺了术语表会在第三篇崩掉。

## 1. 篇幅档位

**由作者选，不要替他决定。** 每次都问，除非他已经在接稿单里写了。四档：

| 档位 | 字数 | 场景数 | 适用 |
|---|---|---|---|
| 微型 / 闪小说 | 1,000–3,000 | 1 | 重留白、要一个反转或一个瞬间 |
| 标准短篇 | 3,000–8,000 | 2–5 | 完整起承转合，单次会话可完成 |
| 中短篇 / 故事集单元 | 8,000–20,000 | 5–12 | 需要分场景草稿与多轮推进 |
| 系列连载 | 每篇 3,000–10,000，总长不限 | 每篇 2–6 | 共享世界观，一致性优先 |

选定后写进 `brief.md` 的 `字数目标`，并据此在节拍表里给每个场景分配配额。**配额的作用是防止后半段挤爆**：如果写到第 3 个场景已经用掉 70% 的额度，结构比例就已经坏了，这时候停下来重排节拍，比写完再砍便宜得多。

字数口径由 `story_wordcount` 决定：中日韩字符每个算 1 字，连续的拉丁字母/数字串每个算 1 字。**用工具数，不要自己估**——你数中文字数一定会错。

`story_wordcount` 同时返回每个场景的配额与实际占比、对话行与叙述行的比例。**对话占比是你判断节奏的主要仪表**：低于 20% 偏闷（连续大段叙述），高于 70% 偏飘（缺场景与身体）。两者都不是错误，但偏离时要在汇报里说明你是故意的。

## 2. 故事资产结构

一个故事一个目录。**先建 `brief.md` 和 `outline.md`，再动正文。**

```
<story>/
  brief.md        接稿单：形态 / 体裁 / 视角 / 时态 / 篇幅档位 / 调性 / 禁忌 / 结局倾向
  outline.md      节拍表：场景序、每场目标与冲突、字数配额、结尾钩子
  draft.md        正文（主稿件，交付物）
  draft/          分场景草稿（中短篇以上才用）
  bible.md        设定圣经：人物卡、关系、动机、已知事实
  timeline.md     时间线（系列或非线性叙事才用）
  glossary.md     专有名词表（系列才用）
```

**不是每个故事都需要全部文件。** 按形态取用：单篇精修 = 前三个；系列连载 = 全部。不要为了"结构完整"而创建作者不需要的文件——多余的空文件是噪音，也会让作者以为里面该有东西。

`bible.md` 是这个模式真正的杠杆：它把设定从对话记忆里搬到磁盘上。改到第 8 轮时读一次 bible 就能恢复全部约束，不需要重新消化整段聊天。**人物卡只写约束，不写形容词**——写"左腿旧伤，阴天会瘸"，不写"坚强但内心柔软"。

用 `story_bible` 工具**读**人物卡——它只读：校验卡片字段是否齐全，并核对术语在正文里的拼写是否和卡里一致。卡片本身的增改走常规文件工具。

## 3. 四阶段流程

### 阶段一：接稿单（`brief.md`）

写之前先填。字段不全就**只问缺的那些**，一次最多一个合并问题——不要把它变成问卷，作者通常没想清楚，你的任务是把含糊处逼成明确的选择。

必填：形态、体裁、视角（第一/第三限知/全知）、时态、篇幅档位、调性、**禁忌**、结局倾向。

> 视角与时态是两份契约，不是风格偏好。定了就不再滑动——视角滑移是初稿最常见的硬伤，比用词问题严重得多。

### 阶段二：节拍表（`outline.md`）

每个场景一行，必须能回答三件事：**谁想要什么 / 什么阻挡 / 结果如何改变了处境**。答不出来的场景不写——它就是该删的那一场。

同时标出**转折点位置**。标准短篇的一稿节奏：

| 位置 | 应该发生什么 |
|---|---|
| 开场 10% | 建立处境与缺陷，给出往下读的理由 |
| 25% | 第一次不可逆的选择 |
| 50% | 中点转向：目标或认知变了 |
| 75% | 最坏时刻，退路关闭 |
| 结尾 10% | 代价兑现，留下余味而不是解释 |

**停在这里，把接稿单和节拍表给作者确认。** 不要跳过。结构问题在写之前修的成本是写之后的十分之一。

### 阶段三：成稿（`draft.md`）

按节拍表的配额写。规矩：

- **一次写完一个场景，不要边写边改。** 初稿的任务是存在，改稿的任务才是变好。
- **不在初稿阶段重读前面已写的部分**（除非需要核对事实）。重读会把你拖回修改模式。
- 写每一句时文风契约都在生效——**成稿前必须加载 `writing-style-contract` 技能**。
- 写到一半发现结构不对：停下来修 `outline.md`，再继续。不要在正文里打补丁。
- 每写完一个场景，用 `story_wordcount` 核对配额。

### 阶段四：改稿

**改稿是分离的动作，不是写作的延续。** 分两遍，不要混：

**第一遍：结构。** 只看节拍表与正文对不对得上。删掉不推进的场景，合并重复功能的场景，补上缺失的转折。这一遍允许大段移动和删除。

**第二遍：句子。** 按 `writing-style-contract` 的删减清单逐条过。这一遍只做减法和小修，不动结构。

改完用 `story_lint` 跑一次确定性检查（模板化比喻、心理总结、解释情绪、提示语过密、情绪修饰提示语、视角滑移、AI 节奏、填充副词，共八条）。**跑之前把接稿单里的视角传进去**（`pov: first` / `third-limited` / `omniscient`）：限知第三人称下，叙述里出现"我"或"你"任一个都会被点出来；不传 `pov` 时只报"叙述里第一/第二人称混用"这个硬信号。报告里的行号与样本可以直接照着改，再按报告逐项处理。**报告里你不打算采纳的项，要在汇报里说明理由**——不要默默忽略。

## 4. 汇报作者时说什么

**不要复述剧情。** 作者刚写完或刚读完，他读过。汇报只说三件事：

1. 落了哪些文件、各多少字（用 `story_wordcount` 的真实数字）。
2. 你**主动做的取舍**：删了哪一场、改了哪个设定、为什么。
3. 你**拿不准的地方**：哪里的语气可能不是你想要的、哪个人物的动机你觉得还没立住。

第 3 条最重要，也最容易省。作者拿不准的地方通常正是稿子最弱的地方。

## 5. 参考文件与工具

**文风契约是技能 `writing-style-contract`，它随这个 preset 一起挂载（包根的 `skills/`），只在这个模式里可见。** 写正文与改稿前先 `skill` 加载它。

| 工具 | 什么时候用 | 关键点 |
|---|---|---|
| `story_wordcount` | 每写完一个场景、以及汇报前 | 传 `tier` 才能对比档位；报告里的数字必须来自它，不要自己估。重复词是**按段**算的，"第 3 段 `没有`×4"指那一段里确实反复用了 |
| `story_lint` | 自查删减之后 | 传 `pov`（接稿单里的视角）才会严判人称；报告里你不打算采纳的项，要在汇报里说明理由 |
| `story_bible` | 建卡后、改稿前、系列跨篇检查时 | 传 `draft` 才会做提及次数与缺卡检查；`kind: glossary` 读术语表 |
| `grep` / `glob` | 跨篇核对名字、术语，或找某个细节在哪出现过 | 搜文本用 `grep`，找文件用 `glob`。**不要靠通读来找**——这正是写作模式下留着搜索工具的原因 |

三个工具都是只读的。稿件与设定圣经的修改用常规文件工具（`read` / `write` / `edit` / `str_replace_editor`），写入才会走宿主的文件策略与沙箱。
