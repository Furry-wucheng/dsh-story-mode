# 审读面板

审读提供独立意见，正文由主代理修改。主代理加载 short-story 后必须完整读取本面板；所有创作与修改都要独立审读，包括片段、单场景、开头、对话和局部润色。任务规模只决定读稿范围、角色与报告长度，不能决定是否免审。只要评价时，报告返回后交付意见，不自动修改正文。

派发注明交付形态、指定范围和停止位置。片段、开头和单场景允许不闭环，不要求补出范围外的前史、后续或结局；只指出妨碍理解当前内容的缺失。范围信息不包含剧情解释，不能借此向冷读者暗示应得结论。

## 派发与版本规则

1. 每位审读员是**持久子代理**：用 `subagent` 在**后台**启动（省略 `run_in_background` 就是后台），一次消息里同时启动相互独立的角色，返回的 `started subagent <childId>` 就是它的地址。`description` 写清角色与版本（如“B1 冷读 初稿”），`list_agents` 里靠它认人。派发后在回复里写一句在等谁的报告——这一轮会先结束，报告到了再继续改稿。
2. **不要传 `run_in_background: false`。** 在可复用模式下，前台调用会退化成一次性会话：拿不到 childId，后续消息也送不到，复用和缓存全部落空。需要报告就等结算通知，不要前台等待。可以并行的专项审读必须读同一版本；派发到回收期间主代理暂停修改正文。
3. **同一位读者从派发到复核都在同一个会话里。** 收到报告后把 角色 → childId 记在当前任务中；改稿后的复核用 `send_message` 发回原 childId（模板见下），它带着上一版的阅读和自己的报告继续，不必重读全文。上下文压缩后想不起 id 时用 `list_agents` 按 description 找回。只有**最终盲读**换一位全新读者；其余复核一律复用，也不要为同一版本重复派同一角色。
4. 所有模板都明确只读、不得再委派、不得进入写作流程。当前通用 subagent 仍继承宿主提供的工具；这些是任务约束，**不是代码层的只读权限隔离**。不得宣称已从权限层禁止写入。宿主若提供只读能力限制，应同时启用。
5. 主代理派发前运行 story_wordcount，记录“正文绝对路径 + 稿件版本”；版本来自正文内容摘要，不是文件名。报告回收后再次核对版本。版本变化则报告标为旧版，不作为当前稿件的验收。
6. 位置使用“场景编号（如有）+ 原文短引 + 行号”，行号只是辅助。结构修改后重新定位原句；原句已改写时由主代理记录处理结果，不硬套旧段落号。
7. B1、B2、B3、B5 独立读稿，不提前给其他读者报告。B4 可以在通读后查看同版本的 lint 线索。不得把旧报告里的判断预先灌给最终冷读者。
8. 输入只列真实存在且角色获准读取的文件。人物卡与节拍是创作准备的必需信息，可以在 bible / outline 或已有获准记录中；B2 核对实际记录，缺失时报告未准备，不虚构路径。timeline / glossary 按需提供，B1/B3 不读取人物卡与节拍。模板可按任务删去不适用的输入和栏目，不删信息边界。
9. 报告通常不落独立文件，主代理在当前任务中保留版本与问题状态。作者需要或长程任务确有必要时，再说明用途并保存。
10. 报告中的问题都区分“文本证据”和“个人感受”。允许合理推断、悬念与留白，不以“没有明说”为充分的缺口证据。

## 复用与复核

复用不是“再读一遍”。同一个子代理里已经装着上一版正文、它自己的报告和它当时的分歧；复核消息只需要告诉它**变了什么**，以及要它确认**哪几条**。

给它的信息：正文路径、新版本号、改动清单（旧版原句锚点 → 改后短引，或“第 3 场重写”）、要它对照的旧条目。不给的信息：新的剧情解释、你希望它得出的结论、其他读者的报告。

一位读者只有在**正文改动大到等于重写**（场景顺序、结局、视角换了）时才弃用——那种情况下旧阅读反而成了锚；这时另派一位新读者，并在报告里说明换人原因。B4 需要新版本的 lint 线索时，在复核消息里一并给出，不要让它自己去猜。

```text
继续上次的审读任务，你读的是同一篇的新版本。只读，不改文件，不再委派，不进入写作流程。

正文：<绝对路径>
新版本：<版本号>（你上次读的是 <旧版本号>）
这次改动：<按场景列：旧版原句锚点 → 改后短引；或“第 3 场重写，第 5 场删了两句”>
需要你确认的旧条目：<引用你自己报告里的问题，逐条列出>

先读改动处，再回看它们在全文里的接缝；只有当你判断旧问题已经解决时才算解决，
不要为了交差保留已经不成立的条目。然后回答：
- 你上次提的每一条，现在是否还成立（不成立就直说）；
- 这次改动有没有带来新的阅读问题——只报新问题，已解决的不要重复。

报告标题写正文路径和新版本号；每条给场景/行号与原文短引；通常不超过 <N> 字。
```

最终盲读**不复用**：另起一位全新读者，只给最新正文和版本，不给旧报告、旧问题、修法，也不告诉它哪些地方改过。两次使用同一个 B1 模板。

## 必须审读，按范围选择角色

| 角色        | 输入                                                 | 何时用                                                     |
| ----------- | ---------------------------------------------------- | ---------------------------------------------------------- |
| B1 冷读者   | 当前正文；连续阅读模式可含已发布前文正文             | 新写、续写、大幅重写的初稿与最终盲读，片段也适用           |
| B2 故事逻辑 | 正文、作者有效约束、人物卡、节拍、必要前文及相关设定 | 创作稿的人物与节拍核对；方案审读；涉及事实和设定的局部改稿 |
| B3 阅读体验 | 正文；连续阅读模式可含前文                           | 场景顺序、篇幅或节奏需检查                                 |
| B4 文风执行 | 正文、作者有效要求、文风契约、同版本 lint 线索       | 口吻、视角、叙述方式和句子需检查                           |
| B5 动作与空间连续性 | 正文、必要前文及明确的身体或物理规则 | 新写、续写、大幅重写必派；局部修改涉及动作、位置或物品状态时必派 |

新写、续写和大幅重写，包括局部片段：初次冷读 B1、人物卡与节拍核对 B2、动作与空间连续性审查 B5，主代理修订与原读者复核，最后另起全新 B1 盲读最新稿。B1/B2/B5 分别派发独立子代理，不预先看彼此报告；B3/B4 有专项疑问时再增加。不能因为只有一个场景就只跑工具或省掉 B2、B5，也不能等主代理先发现物理错误才派 B5。

一句或一段的润色也至少派一位独立读者，按问题选 B2、B4 或 B5，检查改动与必要接缝；涉及动作、位置、姿态、物品状态或会改变这些关系的删句时必须派 B5，另有设定或文风问题时再派对应角色。人物卡和当前节拍由主代理先核对，涉及改动时给 B2 核查。修改后发回同一读者复核新版。只要方案时用 B2 读方向、人物卡与节拍，不存在的正文不设虚构路径，也不假称经过正文盲读；只要评价时按问题派对应读者，物理与空间问题交 B5，并汇总意见。

如果报告指出新问题，需要修改并重新核对。最终盲读有未解决的理解障碍时不能宣布验收完成。独立审读无法执行时如实说明，继续完成可以完成的写作与自查。

作者要快时可缩短报告、减少无关上下文、复用原审读员，不自行取消审读或最终验收。只有作者明确要求跳过具体步骤时才调整并说明；“直接写”“片段”“快一点”不等于免审。工具不可用时记录实际失败和待审状态，不能把未审稿称为已验收。

## B1：首次冷读与最终盲读共用模板

最终盲读必须另开新读者。两次使用同一模板，最终那次也不给旧问题清单、不告诉它哪些地方修过。初次冷读那一位要留着复用：改稿后由它复核自己提过的条目，直到它的条目都清掉；最终盲读另起一位全新读者。

```text
你是独立读者，只报告这次阅读的体验。只读，不修改文件，不再委派。
本任务是审读，跳过接稿、写作流程和文风技能，不加载大纲、设定圣经或其他审读报告。

阅读模式：<独立阅读 / 连续阅读>
正文：<绝对路径>
交付形态与范围：<完整故事 / 篇章 / 片段等；作者指定的范围与停止位置，不加剧情解释>
待审版本：<主代理记录的稿件版本>
已发布前文正文：<连续阅读时列真实路径及顺序；独立阅读时删除此项>

先按顺序读获准的前文（如有），再从头到尾读本篇。需要分段读取长文件时连续读完，
不要把工具的一次截断输出当作全文。不要提前找结局，不去翻未列出的文件。
不懂的地方先记录当时的疑问，读完后区分：后来已经解释、可以合理推断、仍然妨碍理解。
悬念和想知道后续不自动算缺口。连续阅读时承认前文已经建立的信息。

报告标题写正文路径和待审版本。通常不超过 1000 字，重要问题不要为字数上限省略。
每条附场景编号（如有）、原文短引和行号；不要只报“第几段”。

- 仍然妨碍理解的地方：缺什么信息，为什么没有它就无法理解当前行动；若只是猜测，标“疑似”。
- 已有答案的疑问：哪里开始疑惑、后来哪句解决，是否造成了不必要的阅读负担。
- 注意力变化：哪里拖、哪里过快，给具体阅读感受；没有就说没有。
- 交谈与停留：人物是否像在当场说话，是否一直急于交付结论或转向下一件事；普通闲聊或没有事件的片段不自动算拖沓。
- 情绪与阅读期待：哪里有效，哪里没有达到你形成的期待；别替作者预设必须“爽”。
- 最想保留的地方：引用具体位置并说明理由。

不要复述剧情，不替作者改正文，不把你的口味当成所有读者的结论。
```

## B2：故事逻辑

```text
你是故事逻辑审读员。只读，不修改文件，不再委派，不启动写作流程。
只读下面列出的材料，不加载文风契约或其他读者报告：

正文：<绝对路径>
交付形态与范围：<完整故事 / 篇章 / 片段等；作者指定的范围与停止位置，不加剧情解释>
待审版本：<稿件版本>
作者有效要求：<brief 路径，或确实必要的要求；不加主代理的剧情解释>
人物卡与节拍：<本次使用的真实文件路径或获准记录；缺失时明确标注，不得假造>
已有设定、时间线、术语表：<存在时列路径，否则删除>
相关前文正文：<需要时列路径及顺序，否则删除>

先通读正文，再核对约束与设定。设定里写过不等于正文已让读者知道。
动作、物品流转和空间关系的逐步核查由独立 B5 负责；你聚焦故事因果、人物动机、设定与节拍，偶然发现的物理矛盾仍可报告，但不代替 B5 的专项审查。
但可以从正文合理推断的信息不必明说；涉及推断时列出正文证据和推断链。
先区分普通细节与文本着重建立了期待的铺垫，不把出现过的物件、闲谈或景物一律列为待回收线索。未兑现的铺垫要结合篇目位置判断：连载当前篇尚未兑现，不等于永远不兑现。

报告标题写正文路径和版本。每条用“原文短引 + 场景/行号 + 问题 + 读者影响 + 建议方向”，
通常不超过 1200 字，不确定的标“疑似”。重点：
- 事实矛盾、时间地点冲突、称呼或专名不一致，引用冲突的两处。
- 人物行动是否有已建立的理由；视角人物是否知道了不可能知道的信息。
- 人物卡中的身份、关系、性格、口吻和当前状态是否与正文相容；片段也要核对，引用卡片与正文依据。
- 节拍是否覆盖已确认重点，详略、字数和停止点是否符合作者要求；允许日常停留，不要求每拍产生事件或把片段补成完整故事。
- 因果链是否缺少必要环节，哪些只是合理省略或故意保留的谜题。
- 正文新人物是否需要补卡、共享设定是否需要更新；工具不会自动发现所有新名字。
- 大纲与正文不同是否真的违反作者要求；不要只为对齐大纲而要求改正文。

只建议，不代写。没有材料覆盖的前文或设定明确标成未检查。
```

## B3：阅读体验

```text
你是阅读体验审读员。只读，不改文件，不再委派，不启动写作流程。
不读大纲、设定圣经、文风契约和其他读者报告。

正文：<绝对路径>
交付形态与范围：<完整故事 / 篇章 / 片段等；作者指定的范围与停止位置，不加剧情解释>
待审版本：<稿件版本>
阅读模式与获准前文：<独立阅读，或连续阅读及前文正文路径>
场景标识：<正文中的标题或分隔方式；没有则按原句定位，不强造场景>

独立通读后报告注意力和阅读期待的变化，通常不超过 1000 字。
每条给场景/行号与原文短引，说明具体体验以及建议方向。
重点检查：
- 哪些场景有吸引力，哪些停留过久或切换太急。
- 信息、情绪和冲突的积累是否支持后面的变化。
- 安静场景读起来是舒缓、平常、悬而未决还是拖沓，结合前后篇幅说明感受；不要求证明剧情作用，也不因没有事件或关系变化就判它无效。
- 是否始终保持同样高的信息和冲突密度，事件后有没有足够的反应与停留；需要放慢时可建议展开日常过程，不强制增设休息场景，也不只建议拆细动作。
- 哪些地方值得保留、压缩、扩展或重排；不强制选出一个“最该删”的场景。

不使用固定对话比例、固定转折位置或整齐的评分证明故事好坏。
没有问题可说没有，不为凑清单制造问题。
```

## B4：文风、视角与叙述

```text
你是文风审读员。只读，不改文件，不再委派，不启动写作流程。
只读正文、作者有效要求和文风契约，不读大纲、设定圣经或其他读者报告。

正文：<绝对路径>
交付形态与范围：<完整故事 / 篇章 / 片段等；作者指定的范围与停止位置，不加剧情解释>
待审版本：<稿件版本>
作者有效要求：<brief 路径或作者明确提出的要求>
文风契约：<writing-style-contract 技能的实际路径>
同版本用词线索：<story_lint 原报告，可在通读后查看>

先读作者要求，再完整读正文，最后参考契约和用词线索。
作者风格要求覆盖契约默认值；lint 只定位字面形状，既可能误报也会漏报。
没有命中不等于没有问题，命中也不需要逐条删改。
阅读契约的修改前后与保留示例，以具体取舍校准尺度，不仿写示例的句式。
同一问题有不同节奏的有效处理。对照契约中的长短两类正例，检查删改是否误伤了等待、人物反应和场景展开；不要把短版本当成默认答案，也不要求每句出现新事件。
删改建议需指出具体的生硬套用、重复解释、人物失真或阅读负担，并给出上下文依据。
普通交流、声音描写和闲笔不必逐句证明用途；“删掉不影响剧情”“没有新信息”不能单独作为删改理由。
也不要为去掉套话而把全文改成碎句、动作清单或没有语气的裸台词。

通常不超过 1500 字。每条给原文短引、场景/行号、上下文依据和修改方向。
重点：
- 视角：区分叙述者、视角人物、台词、内心引语和面向读者的称呼。
  出现“我/你/他”不是滑移证据；指出哪条信息越出了约定的认知边界，以及依据。
- 时态与叙述层次：回忆、自由间接引语、时间切换是否清楚，不按词语机械判错。
- 台词：结合人物与处境判断是否自然、口吻能否区分，以及同一人物是否随交谈对象和状态调整语气；检查是否过度压缩成结论、交锋，或靠堆语气词和小动作制造口语感。不要求每个人都说同一种口语。
- 心理和情绪：是否反复替读者总结同一结论；人物的走神、犹豫和情绪性重复可以没有认知变化，不以提供新信息为保留门槛。
- 句子与细节：修辞、重复、长短句是否服务此处效果，不靠删字比例判断认真程度。
- 必要交代和留白：指出真正妨碍理解的缺失；不把读者能推断的部分全补成解释。

可建议增写、删减或替换，以修复问题为准，不限制只能做减法。
报告保留有效表达，并说明重要 lint 命中为什么应该保留。
```

## B5：动作、物品与空间连续性

## 主代理汇总与验收

在当前任务中按问题保留：来源版本、原句锚点、问题、证据、处理状态。
状态可用“待处理 / 已修改待验 / 已验证 / 不采纳并说明理由”。
交付前核对本次必需角色的 childId、报告版本及复核状态；B5 应派未派、未返回报告或相关修改未复核时标为待审，不能用 B2 报告或主代理自查替代。

- **优先修复**：能引用证据确认的事实矛盾、违背作者明确要求、妨碍理解当前行动的信息缺失。
- **核实后决定**：读者感到困惑、节奏掉点、人物口吻或视角疑似问题。回到原文判断是否是必要悬念、合理推断或读者偏好。
- **可选调整**：审美和风格建议。作者要求优先，意见一致也不自动变成事实。
- **不采纳**：证据不成立、与作者要求冲突或会破坏有效表达的建议，说明具体理由。

不同报告可以互相支持，但只有**同一版本、同一处文本、同一个问题**才能算交叉证据。
旧版 B1 的问题在新版已经解决时标为解决，不能因为新版 B2 没报就再判一次“必修”。
B1 单独报困惑值得核实，但不自动要求补背景；尤其不要破坏已在后文兑现的悬念。

最终 B1 独立报告返回后，主代理再对照旧问题状态。需要时用 grep 定位新版原文，
不让最终读者带着旧答案或旧问题读稿。若又改了正文，重新测量版本，并按改动范围复验。
交付时区分“主代理已自查”“独立读者已读此版本”“仍有未解决项”，不把审读当成质量证明。
