# 共用写作流程

完整故事、局部片段、单场景、开头、对话、续写和改稿都使用本流程。先遵守 short-story 入口的材料边界与接稿要求；篇幅、规划覆盖范围和审读输入可以缩小，人物卡、节拍和独立审读不能默认省略。

## 1. 接稿与方向确认

先区分已有要求、作者明确授权自拟的项目和仍缺的选择。对新写、续写询问缺失的篇幅字数、内容重点与基调、关系和口吻、视角以及本次写到哪里；不要给片段附加全篇结局的问题。用 ask_user_question 一次问完，未获答复前不写正文。

“角色自拟”不包含“字数你定”；作者没有给数字或区间时必须问目标字数，除非明确把篇幅决定权交给你。完整作品的微型 3000–5000、短篇 5000–10000、中短篇 10000–20000 仅供选择，片段可以采用任何作者确认的长度，不设最低字数。

把确认结果记入 brief.md 或已有接稿记录，标清作者指定与授权自拟的内容。拟定人物与节拍后给简洁方案，等待确认；已有同一方案的批准或明确免确认指令时直接沿用，不反复问。

## 2. 动笔前准备人物卡与节拍

新项目通常使用下面四类文件；沿用已有文件名也可以，同类内容可以合并保存，但不能缺项：

| 文件 | 必须保留的信息 |
|---|---|
| brief.md | 本次形态、范围、目标字数、内容重点、基调、视角、限制、停止点和确认状态 |
| bible.md | 本次出场的主要人物卡及必要的共享事实 |
| outline.md | 当前篇或片段的节拍顺序、详略、篇幅分配与停止点 |
| draft.md | 正文 |

续写和改稿先读取获准的人物卡与节拍，沿用有效内容，补充新增或受影响部分。只改一句也要核对该句属于谁、对谁说、当前状态与所在节拍；没有人物卡和节拍时从获准原文整理最小记录，不能因为正文短就跳过。纯景物等没有出场人物的任务标注人物卡不适用，仍保留视角和节拍；不得为填卡硬加人物。

### 人物卡

每位主要出场人物至少记录身份、当下动机或需要、关系、性格与说话习惯、当前状态和相关既定事实。需要外形、物种或特殊能力的题材，记录本段会用到的特征和限制；没有依据的事实标待定，不冒充已有设定。人物卡不用扩展成完整生平。

~~~markdown
## 林远（别名：阿远）
- 身份：夜班司机
- 动机：下班后想歇一会儿，今天不急着走
- 关系：林青的哥哥，两人平时互相打趣
- 性格与口吻：对乘客客气简短，和妹妹会絮叨；疲惫时反应慢半拍
- 当前状态：刚结束夜班，有些困
- 相关事实：此段发生在车站候车室，不补写他离开之后的事
~~~

卡片给作者与主代理核对，也供 B2 审读；冷读者 B1 不读卡片。不要把卡片逐项塞进开头，正文只交代理解当前内容所需的信息。story_bible 的字段检查只覆盖身份、动机、关系等工具已有能力，不证明人物塑造或其他卡片内容合格。

### 节拍

节拍描述读者按什么顺序经历当前内容，并非每一拍都必须推进事件。记录各拍的主要内容、人物状态或注意力、快慢详略及预计字数；各拍的预算应与已确认总字数一致，写到最后一拍的停止点即可。

例如一个候车片段可以安排：进入候车室与必要介绍 → 随口聊几句 → 安静坐着看窗外 → 广播响起时停笔。中间的闲聊与停留无需带来关系变化，不必另设冲突或把所有细节变成伏笔。此例不规定拍数或比例，人物和场景也不能直接搬用。

#### 关系轴：每一拍都要能回答“谁推动”

**每一拍除内容与字数外，还要写清三件事**——这是节拍表的必需列，不是可选项：

| 列 | 要写什么 |
|---|---|
| 双方状态 | A 的处境/认知 → B 的处境/认知（只写这一拍真的变了的） |
| **推动者** | 这一拍里**具体是谁的哪一个动作或哪一句台词**改变了状态。写成一个动作或一句台词，不写“气氛变化”“关系升温”这类结论 |
| 代价 | 改变的一方放弃了什么。没有代价的改变不成其为改变 |

由此得到两条硬规则：

- **不改变任何一方状态的拍，是重复场景，不是节拍。** 合并它，或者给它一个改变。允许闲笔与停留，但闲笔要出现在某拍的内部，不能整拍都是闲笔。
- **主线上的每一跳（第一次松口、第一次越线、第一次被撞见、关系发生实质变化的那一拍）都必须有一个写得出动作或台词的推动者。** 写不出来，说明缺一拍——补在它之前，而不是在成稿后靠补注解决。

**“推动者”这一栏最常暴露的毛病是单侧失衡**：一个片段或一篇里，若绝大多数拍的推动者都是同一个人，另一个人只是回应、退让、给出规则，那么另一个人物在读者眼里就是“空”的，转折会被读成突兀。规划阶段就要数一遍推动者分布；失衡时补那个被动方的一次主动动作。

**动心的一方必须有一次“不可否认”的露出。** 如果一段关系要发生变化，改变的那一方在此之前必须至少有过一次**只能被读成动心、无法被解释成尽职/礼貌**的露出——而且要有代价（被另一方看见、他马上补救）。全部露出都能双向解释时，读者会合法规避每一条，最后判定转折没有铺垫。这一条属于规划内容：写进节拍表，成稿前先过 §4.0。具体怎么判断“可否认”，见[审读面板](review-panel.md)的 §4.0。

#### 台词的功能分布：也要在节拍表里定下来

节拍表里除了“谁推动”，还要为每一场标注**对话的功能分布**。台词最容易出现的一种毛病是**每一句都在交付信息或下判词**——没有人随口附和、没有人重复、没有人答非所问、没有一件聊完就放下的小事。整篇读起来就会像双方都在念台词，而不是两个人在说话。

两条规划要求：

- **每一场对话里至少要有一处“无功能”交流**（随口附和、确认听清、自我纠正、绕开问题、聊一件小事后自然结束），而且它不必在后续兑现。这条对应文风契约第四节的“给对话留下实际交谈的过程”：那一节列的形式在成稿里常常一个都没落地，因为规划阶段没有为它留位置。
- **“看穿”的能力要单向、向下，并且是当场推出来的。** 一场里最多让一个人显得比在场的人懂得多，而且他要把它用在一个**地位更低或更被动的人**身上（老师对学生、前辈对新人）——反过来的“学生一眼看透大人”是读者最容易读成上帝视角的形态。他对同辈和上位者应该显得迟钝。**并且他说的结论必须建立在这段对话里已经给出的证据上**（谁说了哪句话、谁做了什么动作）：不要让他评点一个读者没看见的事实。角色比读者先知道、又不给证据，读者不会觉得他敏锐，只会觉得作者在借他的嘴交代剧情。

区分“节拍”和“场景”：一个场景里可以有多拍，不为让工具识别每拍而给正文加标题或分隔符。story_wordcount 的 sceneTargets 应按正文实际场景汇总目标；没有场景目标时省略该参数，仍然要有节拍计划。篇幅以作者要求为准，不机械凑字。

### 方案确认

给作者看的方案包括人物关系与口吻、节拍安排（含每一拍的推动者）、目标字数及停止位置。不要求每场都有转折，不给片段强加终局。作者确认或明确免确认后才写正文。规划中的新选择如果超出此前授权，单独指出让作者确认。

**方案先过 §4.0，再动笔。** 关系轴审读（§4.0）在**任何正文落地之前**跑一次：人物卡与节拍拟好后，按面板的“方案审读”派 B2，要它回答“主要那一跳由谁推动、另一方的动心凭什么不可否认”。**这是整个流程里最便宜的一次拦截**——成稿后才发现缺一拍，代价是重写整场；方案阶段发现，代价是一句话。写正文之前没有做过 §4.0 的，标为规划未审。

## 3. 成稿与主代理自查

先加载 writing-style-contract。按人物卡和节拍成稿，保持人物声音、关系、事实与视角一致；对白保留自然交流，日常细节不必后续兑现。停留、等待、观察都可以占用篇幅，不把慢节奏写成更多紧张的小动作。

正文到指定停止点停止，不追加前史、后日谈、关系定论或完整故事闭环。局部修改只处理授权范围；若需要联动范围外的文本，说明依赖，不擅自修改或读取。

完成初稿后回读正文，核对人物卡、节拍和作者要求，运行 `story_wordcount` 实测字数，按需用 `story_bible` 核对卡片字段。`story_lint` 只在自查和修订时用来定位字面形状（疑似套话、需要回看的那一行），**它的命中不构成违规，也不进审读流程**——文风是否合格由 B4 对照契约判断。超过或不足目标时检查详略与内容，修正或明确说明偏离，不能私自重定目标。工具检查和主代理自查是进入独立审读前的准备，不是审读替代品。

## 4. 独立审读与修订

主代理已经在入口完整读取[审读面板](review-panel.md)，派发规则与五个角色的触发条件都在那里；当前上下文没有完整内容时，派发前再次读取。

### 4.0 关系轴审读（先于上面那张角色表的常规轮次）

常规审读都发生在正文落地之后，问的是“**这里有没有矛盾**”。它们答不了另一个问题：**“这一跳有没有依据。”** 两者是相反的测试——一份处处自洽的稿子可以在主轴上完全空心，而五个角色都会正确地不报它（见面板 §4.0）。

所以关系轴单独走一次，**由 B2 承担**（它是唯一读人物卡与节拍的角色），分两个时机：

1. **方案阶段（默认，必做）**：人物卡与节拍拟好后、写正文之前派一次。要它回答：主线每一跳的推动者是谁、另一方的动心有哪些露出、其中哪些是**不可否认**的、被动方有没有主动动作。它读的是节拍表与人物卡，没有正文。
2. **首次成稿后**：随常规 B2 轮次一起派，用正文核对方案里承诺的那些推动者与露出是否真的落在文本上。三处结构改动（补拍、改推动者、改关系状态）后按新写处理，重跑这一项。

关系轴报告的结论要**引用原文（或引用节拍表条目）**，不接受“整体尚可”“铺垫基本到位”这类判断。报出的缺拍按“优先修复”处理，不归入“可选调整”。

### 常规轮次

- **谁在什么时候派，以面板的角色表为准**：B1 冷读与 B2 故事逻辑每个版本都派；B3 阅读体验、B4 文风执行、B5 动作与空间连续性命中各自的可观测条件就派。条件是判据，不是“我觉得需不需要”。
- 五个角色各有一个专用工具（`subagent_review_b1` … `subagent_review_b5`）。人设、阅读边界、报告格式与只读限制已经装在角色身上，派发时**只给变量**：正文路径、待审版本、交付形态与范围、阅读模式、按角色需要的材料路径。不要再从面板抄模板，也不要再写“不许改文件”这类请求——`toolFilter` 已经在权限层剥掉了写入与再委派。
- 审读员用后台派发（省略 `run_in_background`），**不要传 `run_in_background: false`**：前台调用拿不到可复用的 childId。记住每个角色的 childId；派发到回收期间暂停修改被读的版本。
- 收到报告后主代理修订，相关问题交**原读者**复核：`send_message` 发回同一个 childId，附新版号、实际改动和它自己的旧条目。想不起 id 时用 `list_agents` 按 description 找回。只有**最终盲读**另起一位全新读者。
- 后续修改只要影响动作、位置或物品状态，就必须交原 B5 复核相关状态链；B5 报告或必要复核缺失时保持待审，B2 核对和最终 B1 盲读**均不能替代**。
- 一句或一段的局部修改同样按触发条件派角色，但至少有一位独立读者检查改动与接缝；不能缩成只跑工具。重写整个场景时按新写处理。
- 只要方案：人物卡与节拍由 B2 审读一致性、范围和篇幅安排，并**必答 §4.0 的关系轴问题**；没有正文就审方案，不假称已完成正文冷读。只要评价：按作者的问题派对应角色，物理与空间问题交 B5，汇总意见，不自动改稿。
- **作者的“我没看懂”是指令，不只是提问。** 作者或读者对**同一处或同一条线**报“看不懂”达到两次，或困惑落在**关系推进、核心动机、关键转折**上时，按结构问题处理：回到节拍表逐拍核对“谁推动”与“不可否认的露出”，找到缺哪一拍。**不得只做句子级修补。** 困惑出现在主线上时，“是不是没写出来”优先于“是不是读者没读到”；把解释补进台词或旁白（“他其实早就……”）不能替代补一拍。

把报告分为事实矛盾、理解障碍、范围或字数偏离、人物与节拍问题、阅读体验和口味建议，逐项处理。不要求照单全改；不采纳要有依据。读者要求片段交代后续、为普通物件回收伏笔，不能仅凭该意见扩大正文范围。独立审读不可用时，交付状态保持待审并说明实际错误，不能自行宣布通过。

## 5. 连载与版本

连载读者可以按顺序读获准的已发布前文正文，但 B1 仍不读人物卡、节拍和作者摘要。不得越过目录限制去找前文；材料不足就报告检查边界。B2 才读取相关卡片、节拍、时间线或术语表。

每次派发记录路径与正文内容版本，报告返回时核对版本。改稿以原文短引定位，不把不同版本的段落号直接比较。最终审读后再实质修改正文，要复验相关范围，不能把旧报告当作新版验收。

## 6. 交付

检查人物卡和节拍是否与已确认方向、实际正文相容；必要时更新受影响的记录。完成最新版本的独立审读与复核后，简短交付稿件路径、实测字数和审读状态。记录审读员、报告版本与处理结果，不能用主代理的自查结论代替报告。

有未完成的读取、规划或审读步骤时如实列明，稿件标为待审，不声称流程完成。作者明确取消某项工作时遵从并说明；“片段”“快写”“角色自拟”本身不构成取消。正文无需写完整部故事，但本次约定范围的创作与审读要做完。
